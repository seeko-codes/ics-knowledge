## ics-learning-support/encoding/86.md

- **stage**: Learning Support / Encoding, Note-taking
- **role**: guide — chunking fundamentals
- **terms**:
  - Chunking — organizing info into meaningful groups sharing purpose/concept/rationale; ↑efficiency, ↓cognitive load
  - backbone — overall structure/scaffold formed by relating the largest chunks
- **claims**:
  - Chunking = higher-order learning act (must analyse similarities/differences, then evaluate their importance)
  - Same info item can belong to >1 chunk depending on "filter" used
  - Chunking is hierarchical/nested — big chunks → sub-chunks → details; can be "unpacked" back down
  - Chunking reduces cognitive load: brain tracks few categories instead of many facts (worked ex: 100 items → 20 → 5)
  - Chunks must form via evaluation/value judgment, not mere similarity-finding — this extra step = 'analyse' vs 'evaluate' distinction in higher-order learning
- **procedures**: "Do it better" remedy — (1) identify points w/ too many branches, group further; (2) ask "why is it important?" to surface chunking dimensions
- **criteria**: >4 branches from a single mindmap point = signal to chunk further
- **failure-modes**:
  - Incorrect chunking symptoms: mindmap lacks clear backbone, looks chaotic/all-over; >4 branches/point; overwhelming relationship volume (unprioritized); retention suffers significantly; study time increases significantly; total learnable volume per sitting drops
  - Diagnostic: lack of "why is it important?" questions during prestudy → poor chunking/weak backbones downstream
- **examples**: 100 items → 20 categories → 5 categories (folder/sub-folder analogy) — demonstrates hierarchical compression + retained per-item recall
- **relations**: feeds question quality (90.md), reverse causality (87.md — contrast), spiderwebbing (diagnostic companion), prestudy (86 note: poor prestudy "why" questions → poor chunking)

## ics-learning-support/encoding/87.md

- **stage**: Learning Support / Encoding
- **role**: Q&A — conceptual pitfall + diagnostic test
- **terms**:
  - Reverse causality (flaw) — info justified as important solely via another piece of info that itself needs memorising; creates closed loop (importance-recall depends on rote-memorised link)
  - closed loop — A justified only by "A creates B"; no connection to prior knowledge or concepts outside {A,B}
  - intuitive chunking — PREVENTS reverse causality (contrast term)
  - importance checklisting, simple Q&A — can INCREASE reverse causality risk (contrast terms)
- **claims**: reverse causality defeats chunk's purpose — adds a new memorisation item instead of reducing memorisation load
- **procedures/criteria** (diagnostic): state "___A___ is important because ___B___" → ask "Would I only know that if I memorised that B is due to A?" → if YES, reverse causality present (importance is rote-justified, not knowledge-network-justified)

## ics-learning-support/encoding/higher-order-learning.md

- **stage**: Learning Support / Encoding, Retrieval and interleaving
- **role**: guide — foundational explainer, higher-order vs lower-order learning/thinking
- **terms**:
  - Expertise — ability to answer any Q/solve any problem; distinguished by "knowledge structure/network" organisation vs novice
  - Bloom's revised taxonomy — referenced framework splitting higher-/lower-order; explicitly critiqued as an inaccurate hierarchy per "latest research" and by scholars generally
  - Higher-order learning — integrated network knowledge via analysis+evaluation (comparing info, judging relative importance); benefits retention/depth
  - Lower-order learning — isolated knowledge; forgotten quickly/easily
  - lower-order burden — amount that must be memorised via lower-order methods; reduced by starting with higher-order methods
  - Sung's practical encoding cycle — named model (Dr Justin Sung); alternative to Bloom's hierarchy — memory/understanding are OUTCOMES of a higher-order-thinking cycle, not foundational base tiers
- **claims**:
  - Higher-order learning PROCESSES → higher-order OUTCOMES; NOT vice versa (asymmetric relationship)
  - Higher-order methods produce BOTH lower- and higher-order knowledge (must understand before comparing); lower-order methods produce ONLY lower-order knowledge
  - Starting with a higher-order method is more efficient — builds networks first, reduces subsequent lower-order burden
  - Multiple orders always required — brain always forgets; retrieval practice needed regardless of order used
  - Higher-order thinking = comparing, trend-finding, grouping, simplifying, importance-judging, relating to big picture. Lower-order = isolated repetition
  - Bloom's hierarchy is criticised/superseded here — memory & understanding treated as OUTCOMES of higher-order thinking, not base-level prerequisites
- **examples**: (1) analyse→evaluate→map worked example → produces higher-order knowledge, retrievable at higher orders after retrieval practice; (2) flashcard/isolated-fact memorisation example → lower-order process yields only lower-order retrieval

Dimensions: process description (comparing/contrasting/evaluating/networking vs rote-memorising/repeating/isolating); subjective feel (challenging/effortful/confusing/back-and-forth vs tedious/time-consuming/straightforward/boring-sleep-inducing)

## ics-learning-support/encoding/higher-order-tiredness.md

- **stage**: Learning Support / Encoding
- **role**: Q&A — managing cognitive load/tiredness during higher-order learning
- **terms**:
  - cognitive load — mental effort/processing from higher-order engagement ("simplistically" labelled)
  - cognitive load tolerance — expands over time via (1) reframing the feeling positively as benefit is perceived, (2) processing-ability growth/adaptation
  - overload — attempting to process more than capacity allows; biological ceiling exists
  - Goldilocks zone — target load zone between under- and over-load
  - new technique overload — mental resources consumed by executing an unfamiliar technique itself, leaving too little for actual higher-order processing
- **claims**:
  - "High-quality" network = relationships critically examined (not just identified) + related to big picture (not isolated) + actively decided w/ alternatives considered (not first/easiest structure)
  - Network refinement is continuous — re-evaluated via further learning + retrieval practice (links interleaving)
  - Higher cognitive-load feeling is inevitable AND necessary for learning-efficiency gains
  - Overload ≠ productive load — hard biological ceiling exists
- **procedures**: Objectives of effective learning (practice instructions, 4 steps): (1) identify how ideas relate to each other; (2) identify how info relates to what we already know; (3) evaluate relationships, decide relevance/importance; (4) build a critically-examined knowledge network
- **criteria**: recommend only 1-2 new techniques learned at a time (technique-overload prevention rule)
- **failure-modes**:
  - Early-stage load feels: different, uncomfortable, confusing, chaotic, challenging (expected, not itself a failure)
  - New technique overload: resources consumed by technique-execution mechanics → insufficient left for higher-order processing
- **techniques to prevent overload**: strategic non-linear note-taking (tracks thoughts/relationships); mini hypothetical mindmaps ("play" with structures before committing); short breaks to summarise/consolidate before consuming more new info (reduces "stray thought" tracking burden)
- **relations**: extends higher-order-learning.md; explicit link to interleaving-table.md ("see interleaving")

## ics-learning-support/encoding/layering-cognitive-load.md

- **stage**: Learning Support / Encoding
- **role**: guide — layering as scaffolding technique tied to cognitive load theory; progression-gated (Ascent 2+)
- **terms**:
  - Layering — mental scaffolding technique; progressively increases detail level while preserving relevance
  - order control — process of deciding what/where to learn next across resources, used to construct layers
  - self-regulated scaffolding — (links Wikipedia "Instructional scaffolding") teaching oneself by deconstructing/reconstructing a topic for manageability
  - layers of learning — the desired output of applying order control
  - mixed layers — how info is typically presented in source material (logic+concepts+details interspersed; logic often unlabelled in headings)
- **claims**:
  - Layering optimises cognitive load, improves retention, reduces overwhelm for large content volumes
  - Brain needs a big-picture relevance frame early when learning a new topic
  - Prestudy = predecessor mechanism — splits cognitive load across sessions to build big picture/relevance
  - True expertise/knowledge is inherently structured in layers, non-linear/omnidirectional; layering deliberately compresses the normally years-long natural formation of this structure
  - Conventional/mixed-layer learning → fluctuating relevance → high difficulty throughout → tiring/inefficient
  - Layered process (3 steps): (1) spend effort upfront on logic/foundation of relevance; (2) work through increasing detail layers, always moving to next most relevant piece; (3) difficulty reduces over time as knowledge network strengthens
  - Result: relevance stays high, difficulty stays in manageable fluctuation, detail increases progressively (vs conventional: relevance fluctuates, difficulty high throughout)
  - Layer contents are NOT given explicitly by source material — learner must construct them via chunking; the source's apparent "logic" may not be the best chunk after independent evaluation
- **procedures**: layered-learning investment sequence — see claims (3 steps)

## ics-learning-support/encoding/prestudy-guide.md

- **stage**: Learning Support / Encoding
- **role**: guide — beginner's guide to prestudying correctly
- **terms**: Prestudy — study done before the main learning event (class/lecture/session); primes brain, reduces overload
- **claims**:
  - Prestudy spreads cognitive load/confusion across multiple sessions vs concentrating overload into a single main event
  - Without prestudy: cognitive overload during main event → hard to recover from, compounds w/ frequency (daily/weekly events), forces shortcuts/compromised performance, feels progressively more overwhelming
  - With prestudy: build big-picture relevance first, detail later → progressively less confusion, faster/easier knowledge building
  - High-quality/comprehensive prestudy = necessary first step to escape the "study grind"
  - Merely covering content ≠ sufficient (lacks retention/nuance/mastery); most learners lack the study-efficiency to prestudy faster than lecture pace, so ironically fall behind instead
- **criteria** ("You've prestudied correctly if..."): clear big-picture understanding; covered entire topic/subtopic (not just one class); no details/facts memorised yet (exclusively big-picture focus); see how major ideas relate/could be grouped; some hypotheses on how concepts relate; feel ready for more detail
- **criteria** ("Correct framing involves..."): avoid smaller details; identify main ideas/groups of ideas; identify key relationships between ideas/groups; gain big-picture understanding
- **criteria (quantitative)**: HS students w/ moderately efficient techniques → prestudy 4-6 weeks of content in a single weekend achievable; if no time available, even a 10-minute skim before class is beneficial (if principles still followed)
- **procedures**: when to prestudy — any time before main event; common strategy = prestudy upcoming week during prior weekend, or morning-of for the day
- **failure-modes**: committing to details too early → activates isolated/lower-order learning, wastes time, makes content harder; most learners misread the intent of prestudy → feel insecure about not memorising details during it
- **relations**: canonical beginner-level "prestudy" guide; feeds layering-cognitive-load.md (shared graph) and prestudy-tls-aim.md (advanced nuance)

## ics-learning-support/encoding/prestudy-tls-aim.md

- **stage**: Learning Support / Encoding
- **role**: Q&A — relates prestudy to TLS (Traffic Light System) / Aim step of Bear Hunter System; progression-gated (Technique Training+)
- **terms**:
  - Traffic Light System (TLS) — simple IBL method taught in Technique Training
  - Aim step — first step of the Bear Hunter System (BHS); BHS = TLS expanded, taught in Ascent stages
  - Inquiry-based learning (IBL) — question/curiosity-driven learning; knowledge built via processing info while answering questions
  - schema development / schema theory — cognitive process of organising/storing knowledge in mental structures (cognitivist-critique term + the theory ICS cites as supporting IBL)
- **claims**:
  - Prestudy = WHEN (chronological step, before main event); IBL/TLS/Aim = HOW (cognitive steps of the learning process) — the key distinguishing claim
  - IBL should ideally BEGIN during prestudy but continues through subsequent study sessions until the topic is adequately encoded (not confined to prestudy alone)
  - Both prestudy and early IBL aim to: (1) find basic relationships via active exploration; (2) create simple networks/schemas; (3) build big-picture understanding quickly — source of common learner confusion between the two
  - IBL controversy: constructivist roots (Dewey, Bruner) vs cognitivist critique (lack of structured guidance → cognitive overload for novices lacking foundational knowledge, may hinder schema development)
  - ICS position: IBL's underlying principles are well-supported when properly structured (schema theory supports IBL for deep understanding IF cognitive load is managed); contention is largely semantic (what counts as "guidance"/"inquiry")
  - No-prestudy fallback: IBL used DURING main event (very challenging) OR AFTER main event (form basic schemas during event, then consolidate/prime/encode w/ IBL afterward — more viable but still suboptimal vs a separate prestudy step)
  - Previously poorly-learned material: must be relearned via IBL almost as if for the first time. Signs relearning is EFFECTIVE: (a) it is difficult (indicates missing schema — manifests as errors/inability to apply knowledge); (b) knowledge gaps found regularly (indicates retention gaps from lack of schema)
- **criteria**: diagnostic signs that relearning-with-IBL is working — presence of difficulty; regular discovery of knowledge gaps
- **figures**: Prestudy vs IBL.jpeg — diagram: prestudy occurs before the learning event; IBL spans from prestudy through later self-study

## ics-learning-support/encoding/spiderwebbing.md

- **stage**: Learning Support / Encoding, Note-taking
- **role**: Q&A — diagnostic article on a chunking-failure symptom
- **terms**:
  - Spiderwebbing — mindmap symptom: excessive scattered/chaotic arrows added retroactively after chunking was done incorrectly (chunks formed w/o order control or importance/retrieval-matching)
  - waterfalling — pattern where all connections spread outward/down a hierarchy w/ no lateral relationships (precursor step before spiderwebbing arrows get added)
- **claims**:
  - Spiderwebbing occurs when chunks are formed w/o order control or importance/retrieval-matching → relationships end up scattered/chaotic
  - Consequences: reduced retention, increased mindmap time, overloaded intrinsic load, unnecessary frustration
  - Root mistake = identifying relationships AFTER chunking (should be BEFORE: find relationships/similarities → evaluate importance → decide chunks)
  - Directly copying a textbook's hierarchy for chunking = passive/biased chunking, common root cause
- **procedures**: better approach — convert textbook hierarchy → flat list (removes hierarchy bias) → identify relationships → convert into meaningful chunks → map (this ordering prevents spiderwebbing)
- **criteria/remedies** ("To avoid spiderwebbing..."): regularly check chunk structure is simplest/most intuitive; if arrows look chaotic, consider merging chunks closer/together; avoid committing to a fixed chunk structure too early — stay open to change; avoid chunking exactly like a textbook; evaluate necessity of each arrow/line — ask what relationship it actually expresses
- **examples**: textbook-hierarchy→spiderwebbed-map (step 1 waterfalling, step 2 spiderwebbing added) vs improved textbook→list→map process — side-by-side diagnosis + remedy

- **relations**: direct symptom/diagnostic companion to chunking (86.md); references "order control" construct (defined in layering-cognitive-load.md)

- **stage**: Learning Support / Retrieval and interleaving
- **role**: Q&A — diagnoses "ineffective"-feeling retrieval sessions, reframes gap-finding as a good sign
- **terms**: conscious incompetence — skill-development stage where a learner recognises their own mistakes after learning correct methods (temporary confidence drop); Dunning-Kruger graph — referenced framework illustrating confidence-vs-competence relationship
- **claims**:
  - Encoding & retrieval = two sides of the same coin; as encoding skill improves, retrieval need reduces (never to zero)
  - Early "learning to learn" phase normally involves: many retrieval sessions, many knowledge gaps, high time investment in retrieval
  - Most learners' "study time" is dominated by ineffective encoding (re-reading/re-writing/re-listening/mindless notes) + repetitive retrieval sessions
  - Learning effective encoding/retrieval → "conscious incompetence" → temporary confidence drop (Dunning-Kruger pattern) — natural, followed by growth if learner persists
  - Retrieval is ineffective when FEW gaps are found at low mastery (counterintuitive reframe) — many gaps found = retrieval is WORKING correctly, not failing
  - Only way to reduce gaps in early retrieval sessions = raise initial encoding quality
- **procedures**: best way to overcome retrieval problems (practice instructions, 3 steps): (1) perform retrieval to high quality per lessons/interleaving table; (2) target the right levels w/ appropriate spacing; (3) gradually develop better encoding skills
- **failure-modes**: common misconception — learners believe "many gaps found" = bad retrieval (actually the inverse); common gap in practice — learners don't use a variety of interleaving strategies (stuck at only higher- or only lower-order; insufficient procedural elements when the topic needs them)
- **relations**: explicit links to interleaving-table.md and spacing.md; the "encoding vs retrieval" framing here is reused verbatim in spacing.md

## ics-learning-support/retrieval-and-interleaving/interleaving-table.md

- **stage**: Learning Support / Retrieval and interleaving
- **role**: table/reference guide — comprehensive interleaving technique catalog crossed by knowledge type (declarative/procedural) × order of learning
- **terms**:
  - Declarative knowledge — fact/concept/logic-based "content material" knowledge
  - Procedural knowledge — action/behaviour/process-based skill-execution knowledge; stored in different brain regions than declarative
  - Conditional knowledge — knowledge of WHEN/HOW to deploy declarative+procedural knowledge; developed via integrative retrieved execution
  - REBIM (Repetitive Execution Beyond Initial Mastery) — Dr Justin Sung-coined; repeating already-mastered tasks; negligible benefit; USELESS-category technique
  - 3Cs (Cover, Copy, Check) — low-level fill-in-blank retrieval: cover notes → rewrite/redraw from memory → uncover+check; effective for short-term basic retention (esp. younger learners); best for labelling diagrams/processes
  - Flashcards — Simple (isolated facts); Simple relational (2-3 concept relationships); Evaluative (holds a generated evaluative question)
  - Generated questions — Isolated; Simple relational; Multi-relational (>2 concepts); Evaluative (requires value judgment on relative importance)
  - Brain dump — Linear (typed, low-mid mastery, good end-stage pre-assessment tool); Mindmap (higher-order testing, good early-retrieval big-gap finder)
  - Teaching — Isolated; Simple relational; Modified Whole-Part-Whole (WPW) — late-stage, hardest technique in program, needs expert mastery + near-mastery of Ascent-stage encoding methods
  - micro-retrieval — teaching/explaining something immediately after learning it, within the same session
  - Practice questions — Direct (answer→check immediately); Extended (answer→evaluate confidence→create perfect answer sheet→check vs official); passive (USELESS — mental-only answers, no real gap-finding)
  - Advanced group method (for practice questions) — composite of generated questions + peer/group discussion + practice questions; 11-step group protocol (see procedures)
  - Peer/group discussion — undirected (USELESS); evaluative (explicit critique/judge/argue goal)
  - Chunkmaps (GRINDEmaps) — core Bear Hunter System encoding technique (Growth phase); foundational skills trained since Fundamentals 2, method not relevant until Ascent 3; used as a RETRIEVAL method to re-encode previously poorly-encoded content
  - Method of loci / Modified Method of Loci, Story/link method, Ben system — memorisation techniques; narrow use cases, lower-order only, risk of over-reliance if learned too early ("over-sold by memory champions")
  - Feynman method — 4-step guided structure (see procedures); superseded by ICS's own methods but retained as a micro-retrieval technique
  - Retrieved execution — Simple (isolated, no variation); Integrative (combines multiple skills into a complex function, builds conditional knowledge — target: move here ASAP after basic competency); Applied (starts from target output, works backwards — most challenging/effective form)
  - Challenges — Simple; Integrative; Edge-case (atypical/unfamiliar context; needs strong declarative knowledge to navigate; easier to CREATE than to solve; can substitute for evaluative generated Qs in advanced group method)
  - Variable modification — same problem, different values/figures (low-level procedural practice)
  - Variable addition — add variable(s) to raise difficulty (requires declarative knowledge to judge sense/solvability/interaction with existing variables); >1 variable addable if viable
- **claims**:
  - Useless-technique category: no circumstance justifies passive re-reading/re-writing/re-listening, REBIM, passive practice questions, or undirected peer discussion — a better alternative always exists for the same time cost
  - AI-use principles: GOOD for — saving time on tedious low-cognitive tasks, consolidating multi-source info, creating test questions (AI-generated preferred over self-generated for time savings + external calibration), exploratory Q&A. AVOID for — checking "truth" of nuanced/complex concepts (LLMs lack ground-truth understanding) and bypassing meaningful cognitive effort (AI-driven chunking/evaluating can push the brain into passive "understanding" mode, hard for beginners to detect — recommend beginners avoid AI-chunking until they have a clear internal sense of active vs passive/cognitive load; if used, always challenge/evaluate AI's chunking for accuracy)
  - Declarative/procedural imbalance: strong procedural + weak declarative → excels at familiar problems, struggles w/ novel challenges (e.g. coder scripting fluently but failing technical interviews); strong declarative + weak procedural → good conceptualisation, poor execution accuracy (e.g. buggy/inefficient code despite good ideas). Truly excellent learners excel at both
  - Predominantly-procedural retrieval schedules are simple/effective because: (1) skills build on themselves → natural consolidation/repetition; (2) retrieval competence ~ directly proportional to practice/feedback/difficulty (straightforward path); (3) lower-order competence is directly tested by higher-order methods (unlike declarative knowledge)
  - Mixed-knowledge-type systems: base on the declarative combination (more time-consuming/challenging), swap in procedural techniques as the procedural component of the topic rises; extra interleaving sessions become unnecessary for high-procedural topics once initial declarative competence is reached
  - Answers must always be generated FULLY (written or typed, never mental-only) — prevents illusion of explanatory depth
  - Teaching should preferably be done OUT LOUD — forces explicit/slowed retrieval, prevents illusion of explanatory depth (quiet speech acceptable to preserve voice)
  - Curriculum scope: aim slightly OUT of scope for optimal results (staying too rigidly in-scope makes re-encoding complex concepts harder); use learning objectives to calibrate degree of scope deviation
  - Spacing accuracy: quality of interleaving matters MORE than accuracy of spacing — schedule can drift by days or weeks if session quality stays good
  - No time available: do your best; as encoding skill compounds, retention/speed improve → eventually "cram" encoding early and shift mostly to interleaved retrieval later, getting ahead of cohort schedule
  - Language learning: no evidence supports withholding retrieved execution (speaking/writing) until "mastery" — rejects popular immersion/comprehensible-input-only claims as misinterpretations of the actual research (including of immersion/CI research itself)
- **procedures**:
  - Feynman method (4 steps): (1) choose a topic; (2) teach it to a child (simple language, no jargon); (3) identify gaps and simplify (note unclear/hard-to-simplify areas); (4) review and refine (return to primary sources, fill gaps, simplify further)
  - Advanced group method for practice questions (practice instructions, 11 steps): (1) choose a topic; (2) form a study group of ≥1 other person at similar/higher level; (3) each person creates a practice exam covering mid-order + higher-order Qs (pure lower-order handled via other methods); (4) create a perfect answer sheet for own exam — brain dump first, then refine against materials; (5) swap exams, keep own answer sheet; (6) answer the swapped exam from memory; (7) mark uncertain answers for review; (8) create a perfect answer sheet for the exam just taken; (9) swap answer sheets; (10) compare own answers against both answer sheets, note differences; (11) discuss/resolve any disagreements together. Generative effects triggered at steps 3, 4, 6, 8, 9, 10. Recommend splitting across multiple days
- **criteria**: order-of-learning × technique mappings (see tables below); spacing-accuracy question deferred explicitly to spacing.md
- **failure-modes**: learners commonly stick to a narrow interleaving repertoire (only higher- or only lower-order; insufficient procedural elements when topic needs them); simple retrieved execution continued past mastery point becomes REBIM (ineffective); Direct practice questions risk hiding the root cause of mistakes / misclassifying real gaps as "silly mistakes"

## ics-learning-support/retrieval-and-interleaving/spacing.md

- **stage**: Learning Support / Retrieval and interleaving
- **role**: Q&A — canonical spacing-schedule article with exact parameters
- **terms**: encoding vs retrieval — "two sides of the same coin" framing, reused verbatim from good-retrieval.md
- **claims**:
  - Better encoding → less retrieval needed, but never zero (brain is never "leak-proof" — constant baseline decay)
  - Encoding & retrieval are NOT fully separate processes — mainstream learning-science view treats them as fundamentally intertwined; ICS separates them only for PRACTICAL/pedagogical reasons (distinct techniques are used to optimise each)
  - "Retrieval failure" (beyond inadequate encoding alone) is a common cause of decay of previously-encoded information
  - Semi-regular/loose spacing is sufficient — an ultra-strict schedule is explicitly NOT necessary
  - With effective encoding, ~80-90% retention achieved by end-of-week revision → 1 week's material revisable in "just a few hours"
  - Each subsequent retrieval session reduces decay + re-encodes info → end-of-month (4-week) revision becomes ≈ a half-day activity
  - Combined with prestudy + ahead-of-schedule batch learning → overall schedule burden is "extremely easy" to sustain
  - Learners with low encoding skill: schedule feels harder to sustain, BUT the fix is MORE retrieval in the short term (not less); retrieval time naturally falls as encoding skill improves
- **procedures/schedule** (exact — core parameters of this article):
  - General rule: same-day, 1 day, 1 week, 1 month spacing intervals, followed loosely
  - Worked weekly example (Day → session type → scope): Monday & Tuesday → same-day retrieval → new material learned+revised same day. Wednesday → one-day retrieval → interleaved retrieval for Mon+Tue content (+ Wed if new material learned that day too). Thursday → same-day retrieval for new content → new material learned+revised same day. Friday or Saturday → one-week retrieval → interleaved retrieval covering last 2 weeks. End of month → one-month retrieval → interleaved retrieval covering last 4 weeks. 3-4 weeks prior to assessment → one-month retrieval+ → retrieve everything relevant for the assessment
  - Resulting cadence: all material revisited within 1-3 days of first learning it, then 1-2 weeks later, then 2-4 weeks later
- **criteria** (exact numbers — capture faithfully):
  - Spacing intervals: same-day / 1 day / 1 week / 1 month
  - End-of-week revision retention target: 80-90%
  - Weekly revision time estimate: "a few hours"
  - Monthly (4-week) revision time estimate: "half-day"
  - Revisit cadence: within 1-3 days → 1-2 weeks later → 2-4 weeks later
  - Total encoding/re-encoding touches per month per material (prestudy + on-day study + interleaved retrieval combined): ~6
- **failure-modes**: perceived-excessiveness misconception — schedule seems too time-consuming to learners w/ low encoding skill, but this is a symptom of low encoding, not a flaw in the schedule; remedy = more (not less) short-term retrieval while encoding skill develops
